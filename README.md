# Cuter

> 纯 Rust 的高性能截图 / 标注 / 贴图工具。同类工具大多跑在 Electron 上，这里**不用 Electron**——目标是「毫秒级启动、十几 MB 体积、几十 MB 内存」。

```
┌──────────────────────────────────────────────────────────────┐
│  Alt+C  →  冻结屏幕  →  框选  →  标注  →  复制 / 保存 / 贴图  │
└──────────────────────────────────────────────────────────────┘
```

**[下载最新版](https://github.com/ChuGe1206/Cuter/releases/latest)** —— Windows 10/11 x64，免安装 zip 或安装包。
暂无代码签名，首次运行会有 SmartScreen「未知发布者」提示。

## 界面

界面按 `docs/design/DESIGN-SYSTEM.md`（现代深色工具风）实现：一个强调色、4px 网格、
层次靠字号与颜色（不靠字重）。设计稿与"稿子 vs 实际"的对照图在 `docs/design/`。

设置窗口已按稿重做（0.1.24）；其余面板正在逐屏推进。

## 为什么再造一个截图工具

| | Electron 系同类工具 | Cuter（**本机实测**，见下） |
|---|---|---|
| 运行时 | Chromium + Node，安装包 150 MB+ | 无运行时，单个 exe **8.6 MB**（便携包 3.99 MB） |
| 启动 | 数百毫秒 | 冷启动到冻结遮罩可见 **555~559 ms**；`--full`（进程启动 → PNG 落盘）中位 **137~168 ms** |
| 按热键到看见遮罩 | — | 托盘模式下 **min 82 / median 147 / max 174 ms**（GDI，5 次；同一台机器不同轮次会在 110~200 ms 之间波动，"多久被读到"那一段只要几毫秒到几十毫秒） |
| 内存（常驻托盘） | 300 MB 起 | 纯待命 工作集 **58.8 MB** / 私有 **28.8 MB**；闲置 30 s 后工作集收到 **6.1 MB**（私有不变，只是把页还给系统）；开着设置窗口时 工作集 149~156 MB / 私有 69~77 MB（含 18.8 MB 系统微软雅黑） |
| 内存（遮罩打开，峰值） | — | 工作集 **~150 MB** / 私有 **~69 MB**，关掉后回落 |
| 截图像素精度 | 受 WebView 缩放影响 | 强制 1:1 物理像素，绝不重采样 |
| 跨平台 | 开箱即用 | Windows 优先，架构已预留 |

> 表里每个数字都是**量出来的**，复现命令见后：`tools/probe/perf_probe.ps1`（内存与 `--full`）、
> `tools/probe/latency_probe.ps1`（热键 → 遮罩）。最近一次全量复量是 0.1.55，用的就是发出去的
> 便携包里那个 `cuter.exe`。
>
> 「内存十几 MB」早就被证伪并改成了实测值（这套栈：egui + OpenGL + 一份 18.8 MB 的系统中文体，
> 压不到十几 MB），但**这些数字会随版本长胖**：README 里的旧记录是 87~97 MB，0.1.55 复量是
> 149~156 MB。这段时间里多出了在线 OCR 客户端、更新检查、自绘托盘菜单等功能，但**没有逐项 A/B**，
> 所以不要把增量归到某一个功能上。数字怎么来的、哪些地方还能压，
> 见 [docs/HANDOFF.md](docs/HANDOFF.md) 第 14 节与第 75 节。

## 当前状态（M1 + M2 + M3 主体完成，商用化第一轮已做）

功能：

- **全屏冻结遮罩**：热键触发后先捕获整个虚拟桌面再显示遮罩，所以画面绝不会在框选过程中变化，也不会拍到别的窗口闪一下。
- **框选吸附**（M2）：自动吸附到窗口与屏幕的边缘/中线，命中时画出贯穿整屏的参考线；鼠标还没按下时会高亮光标所在的窗口作为预告；**按住 Alt 临时关闭吸附**。
- **框选**：八向控制点、方向键微调（1px / Shift 10px）、Ctrl+A 全选、Ctrl+R 复原上次选区、双击确认、右键取消。
- **放大镜 + 取色器**：8 倍放大跟随鼠标，实时显示 `#RRGGBB`、`rgb()` 与全局像素坐标。
- **标注**：矩形、椭圆、箭头、画笔、荧光笔、马赛克、模糊、文字、序号；颜色与线宽可调；撤销 / 重做（撤回栈有上限，长会话不会吃光内存）。
- **文字识别（OCR）**：框选后 `Ctrl+O` 弹出**左图右文**的结果面板——左侧预览上叠着识别出的文本块（悬停高亮、单击复制该行），右侧是可编辑的识别文本（校对后再复制）。默认用 **Windows 自带的 OCR**：零下载、零打包、完全离线，中文开箱即用；识别在独立后台线程上跑，不卡界面。
- **滚动截屏（长截图）**：`Alt+S` 或工具条上的滚动按钮进入滚动模式，框选后回车开始采集，**你自己在目标窗口里往下滚**，程序定时抓同一块区域并用逐行签名匹配求出位移、增量拼接。旁边的控制窗显示实时缩略长图与帧数，回车完成 / 空格暂停 / Esc 取消。控制窗会自动避开采集区域，避免被截进长图。
- **输出**：复制到剪贴板、保存到文件（PNG / JPEG / WebP / BMP，JPEG 质量可调）、原生「另存为」对话框、**贴到屏幕上**（滚轮缩放、可调不透明度、鼠标穿透、外部投影、可选的「只放大内容不改窗口尺寸」）。
- **托盘 + 全局热键**：默认 `Alt+C` 框选、`Alt+X` 当前显示器、`Alt+S` 滚动截屏、`Alt+V` 贴图、`Alt+O` 识别剪贴板图片（未实现）。关掉设置窗口默认只是**退到托盘**，托盘与热键继续有效；**再启动一次不会多开进程**，而是把这次启动转交给正在跑的实例（`--capture` 会让它直接开始框选）。
- **命令行**：`--full` / `--monitor` / `--region` / `--list-monitors` / `--pin` / `--tray` 等，用于脚本与自动化。无界面用法在 cmd / PowerShell 里会被正常等待、stdout 可重定向、退出码可传递。
- **出错有据可查**：日志同时写 stderr 与 `%APPDATA%\Cuter\logs\cuter.log`（2 MB 滚动、保留 3 份，设置 → 诊断里有「打开日志目录」）；panic 会写成 ERROR 日志并（界面模式下）弹出说明框；配置是原子写入的，断电不会留下半个 `config.toml`。
- **开机自启**：设置 → 通用里的一个勾选框，写 `HKCU\...\Run`（默认关）。启动时会与注册表对账，但**只删指向自己的那一条**——便携版不会把已安装版本的自启项顺手删掉。
- **常驻内存 ~57 MB 工作集 / ~29 MB 私有**（托盘常驻、还没截过图时）：界面字体按需装载，没窗口要画就不读那 18.8 MB。
- **捕获后端可切换**：默认 GDI（兼容性最好），可选 `capture.backend = "dxgi"` 走 DXGI 桌面复制——本机实测整屏 **11~15 ms** vs GDI 42~107 ms（约 4 倍），像素与 GDI 完全一致；RDP / 被别的录屏程序独占时自动回退 GDI。设置 → 截图 页可选。
- **没窗口要画时自动卸掉界面字体**：设置窗口一关，工作集从 82 MB 回到 56 MB。
- **贴图省内存**：分组切走/隐藏的贴图立刻释放纹理（实测 −75 MB），切回来自动重建。
- **自动滚动截屏**：按 `A` 让程序自己滚（默认关；部分程序忽略合成滚轮）。
- **文件名模板**：{app}（按热键时的前台程序）、{monitor}、{date} {time} {seq} {w} {h} 等占位符。
- **贴图图片圆角**（可关）。
- **托盘通知可关**：启动时提示一次热键、保存后提示文件名（general.show_tray_notifications）。
- **托盘待命 GPU ~0.08%**（空转重绘降到 1 fps；热键延迟不受影响，有探针钉住）。
- **启动 ~364 ms**（进程创建 → 第一帧，本机中位；诊断页会显示你机器上的实测值）。
- **界面多语言**：简体中文 / English 一键切换（设置 → 通用 → 语言），282 条文案全覆盖。
- **OCR 对照**：识别结果面板里按 `L` 切到「逐行对照」，鼠标指哪一行、图上就高亮哪一块；在图上点一块，右边落到对应那一行。
- **滚动截屏**：纵向 / 横向、往下 / 往上都行，方向自动判定；往回滚到已拍过的内容不会重复。
- **控件级吸附**：悬停会吸到光标下的按钮/输入框，点一下就精确选中它；窗口空白处仍吸整窗（按住 Alt 临时关掉）。
- **贴图拖出**：贴图上 **Ctrl+左键拖动** 或 **中键拖动**，可以把这张图直接拖进资源管理器、微信、浏览器里（中键单击仍是恢复 100%）。
- **贴图分组**：Alt+V 贴图后，Alt+H 隐藏/显示当前组、Alt+G 切到下一组（也可用 `cuter --toggle-pins` / `--next-pin-group`，方便绑到别的工具上）。设置 → 贴图里能看到每组有多少张。
- **截图历史**：每次成功交付的截图都会存一份**无损原图** + 缩略图（`%LOCALAPPDATA%\Cuter\history`，便携模式跟着 exe）。托盘菜单「截图历史…」或 `cuter --history` 打开面板：一行一张，可**再复制 / 再贴图 / 另存为 / 删除**，顶部显示张数与总占用，一键清空。保留张数可调（默认 30，`0` = 关闭）。

## 发布产物

```shell
cargo build --release

# 免安装 zip：解压即用，配置 / 日志 / 截图都跟着 exe 走（打包脚本自己会验证便携性）
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\package\portable_zip.ps1
# → dist\cuter-<版本>-portable-x64.zip

# 安装包：开始菜单 + 可选桌面图标 + 可选开机自启 + 卸载保留用户配置
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\package\build_installer.ps1
# → dist\cuter-<版本>-x64-setup.exe（缺工具链时会自动取一份免安装的 Inno Setup 6）
```

安装包按用户安装（默认 `%LOCALAPPDATA%\Programs\Cuter`，**不需要管理员权限**），
卸载时保留 `%APPDATA%\Cuter` 里的设置、日志与截图。两个打包脚本都把版本号取自
exe 自己的版本资源，和程序不可能对不上。

exe 带版本资源与图标（`build.rs` 把 `assets/cuter.ico` 编进资源段，
图标本身仍由 `src/icon.rs` 在运行时画给托盘与标题栏——**改了图形要重跑**
`cargo run -p cuter-app --example dump_icon -- crates/cuter-app/assets/cuter.ico`）。

**便携模式**：exe 旁边放一个空的 `cuter.portable`，配置 / 日志 / 数据 / 默认保存目录
就全部落在 exe 旁边（`Screenshots\`），不再写 `%APPDATA%`。

> ⚠️ 目前三种产物都**没有代码签名**，首次运行会有 SmartScreen 的"未知发布者"提示。

## 为什么 OCR 用系统自带的，而不是打包 PP-OCR 模型

本项目的硬约束之一是**存储占用要小**。PP-OCR 的 det + rec + 字典加上推理运行时
通常是几十 MB 级别；而 Windows 10/11 自带 `Windows.Media.Ocr`，**零下载、零打包、
完全离线**，中文只要系统装了语言包就能用。

实测同一张 1400×700 的屏幕截图，识别耗时约 **130 ms**，中英混排都能读出来。
需要更高精度时，`config.ocr.engine` 保留了 `Http` 选项用来接自建服务。

闭包测试见 `crates/cuter-ui/tests/ocr_windows.rs`：**用我们自己的 CPU 栅格化器把
「Hello Cuter 12345」画进一张图，再用 OCR 读回来**，两边完全一致——一次覆盖了
栅格化与识别两条链路。

## 设计原则：设置里的开关必须真的生效

截图工具最容易被用户识破的地方，是设置面板里摆着一堆**改了没反应**的开关。
本项目把「每一个开关都能在代码里找到它的作用点」当作硬性约束，并在 M2 里
把 M1 遗留的假开关全部接上：包含鼠标指针（真的把光标合成进像素）、
延迟捕获、窗口吸附、区域记忆、自动保存、另存为对话框、贴图不透明度与鼠标穿透。
如果某个能力还没做，就不要在界面上给它一个开关，而是在路线图里写明。

商用化第一轮又把**所有**配置字段对着代码搜了一遍，补齐了剩下的 6 处
（保存质量、贴图滚轮缩放 / 窗口内缩放 / 投影 / 置顶、关闭到托盘、OCR 段落模式），
并删掉了 3 个从未实现的占位字段。完整的对照表在
[docs/config-audit.md](docs/config-audit.md)——**新增配置项时必须同步更新它**。

## 快速开始

### 环境要求

- Rust **1.88+**（使用 edition 2024 与 let-chains）
- Windows 10/11 + MSVC 工具链（`x86_64-pc-windows-msvc`）

### 构建

```shell
git clone <repo> && cd Cuter

# 开发（依赖按 opt-level=3 编译，自身代码 opt-level=1，迭代速度快）
cargo build

# 发布（LTO + codegen-units=1 + strip，体积最小 / 速度最快）
cargo build --release

# 极致体积（牺牲少量热点算力）
cargo build --profile release-small
```

产物在 `target/release/cuter.exe`。

### 运行

```shell
cuter                            # 托盘常驻 + 设置窗口
cuter --capture                  # 启动后立刻框选
cuter --full --out shot.png      # 无界面截取整个虚拟桌面
cuter --monitor --copy           # 无界面截取当前显示器并复制
cuter --region 0,0,1920,1080     # 无界面截取指定区域
cuter --list-monitors            # 打印每台显示器的物理/逻辑尺寸与缩放率
cuter --help
```

### 遮罩内的操作

| 操作 | 行为 |
|---|---|
| 拖拽 | 框选区域 |
| 拖拽选区内部 | 移动选区 |
| 拖拽控制点 | 拉伸选区 |
| 方向键 / Shift+方向键 | 1px / 10px 微调 |
| `Ctrl+A` | 全选整个虚拟桌面 |
| `Ctrl+R` | 复原上次框选区域 |
| 按住 `Alt` | 拖拽时临时关闭吸附 |
| `Enter` / 双击选区 | 复制并关闭（**滚动模式则是开始采集**；勾了「框选后立即识别」则是 OCR，勾了「自动保存」则是保存） |
| `Ctrl+C` / `Ctrl+S` / `Ctrl+T` / `Ctrl+O` | 复制 / 保存 / 贴图 / 识别文字 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |
| `Esc` | 第一次取消选区，第二次退出 |
| 右键 | 取消选区 / 退出 |

### 滚动截屏控制窗的操作

| 操作 | 行为 |
|---|---|
| 在目标窗口里滚动 | 程序定时抓同一块区域，自动把新内容拼到长图下方 |
| `Enter` / 空格 | 完成并交付（复制或保存，跟随 `save.auto_save`） |
| `Esc` / 关闭窗口 | 放弃这次滚动截屏 |
| 「暂停」按钮 | 暂停采集（比如中途要看别的地方） |

## 架构

```
crates/
├── cuter-core/     平台无关核心：几何、位图运算、屏幕捕获抽象、配置、OCR 接口
│   ├── geom.rs         整型像素几何（虚拟桌面坐标系允许负坐标）
│   ├── frame.rs        RGBA8 位图容器 + 裁剪 / 模糊 / 马赛克 / alpha 合成 / 编码
│   ├── capture/        捕获抽象
│   │   ├── windows.rs      GDI BitBlt 屏幕捕获后端
│   │   ├── win_windows.rs  顶层窗口枚举（框选吸附用）
│   │   └── cursor.rs       鼠标光标位图提取（「包含鼠标指针」用）
│   ├── config.rs       TOML 配置（永不因配置损坏而启动失败）
│   ├── scroll.rs       滚动截屏：行签名匹配 + 增量拼接（纯逻辑，完全可无头测试）
│   └── ocr/            OCR 接口与结果模型 + Windows.Media.Ocr 引擎
├── cuter-ui/       界面层：只依赖 egui / cuter-core，不碰任何平台 API
│   ├── overlay.rs      全屏冻结遮罩：状态机、框选、吸附、放大镜、快捷键
│   ├── snap.rs         吸附的纯几何（窗口/屏幕的边缘与中线）
│   ├── annotate.rs     标注模型、文档、撤回栈（分区像素快照）
│   ├── flatten.rs      把标注真正画进像素（导出用 CPU 栅格化）
│   ├── toolbar.rs      浮动工具条（图标全部矢量绘制，不依赖图标字体）
│   ├── pin.rs          屏幕贴图窗口
│   ├── ocr_panel.rs    OCR 结果面板（左图右文）
│   ├── scroll_panel.rs 滚动截屏控制窗（缩略长图 + 完成/暂停/取消）
│   ├── theme.rs        配色与视觉常量
│   └── fonts.rs        系统中文字体探测（egui 自带字体没有 CJK 字形）
└── cuter-app/      应用层：eframe 多视口、托盘、热键、剪贴板、原生对话框
    ├── app.rs          视口编排、截图流程、设置界面
    ├── save_dialog.rs  原生 IFileSaveDialog 封装
    ├── desktop.rs      全局热键 / 托盘 / 剪贴板
    └── icon.rs         运行时用代码画出应用图标
```

几条贯穿全局的设计决定，都写在对应模块的文档注释里：

1. **坐标只有一种：物理像素。** 遮罩窗口强制 `pixels_per_point = 1.0`，让 egui 的「点」等于屏幕像素。这样鼠标位置不需要换算，冻结帧 1:1 贴到窗口上，系统缩放（125% / 150%）不会把截图重采样。
2. **标注挂在冻结帧上，而不是选区上。** 于是移动 / 拉伸选区不需要改动任何标注，马赛克与模糊也自然跟着走，导出时只需一次裁剪 + 一次平移。
3. **只加载会变化的数据纹理，撤回只存受损区域。** 4K 截图下一次马赛克的撤销内存开销是几十 KB，而不是重新克隆 33 MB 的整图。
4. **捕获与界面解耦。** `ScreenCapture` / `WindowDetector` 两个 trait 把平台差异关在 `cuter-core` 里，UI 一行都不用改。
5. **core / ui / app 三层单向依赖。** `cuter-core` 不依赖 egui，因此它的测试可以完全无头运行。
6. **吸附是纯几何。** `snap.rs` 不碰任何 Win32，平台相关的只有「把窗口矩形列出来」；因此吸附的边界情形（贴边、共享边、负坐标、退化矩形）全都有单测。

## 已知限制

- **多显示器混合缩放**：全屏遮罩是一个跨越整个虚拟桌面的窗口。如果各显示器缩放率不一致，Windows 会强制调整跨屏窗口的尺寸，遮罩可能无法精确对齐。此时请使用「截取当前显示器」。程序会在设置 → 诊断里主动检测并提示。
- **工具条不随系统缩放放大**：1:1 像素映射与「按 DPI 放大界面外壳」是互相冲突的两个目标，目前选择了前者（截图内容必须精确）。界面外壳的自适应缩放仍在路线图上。
- **吸附只到窗口边缘，不到控件**：贴合窗口内部的按钮/输入框需要 UI Automation，排在 M5。
- **滚动截屏只支持向下滚动**：检测到回滚会提示；内容整个换掉或完全周期性时匹配会失败并提示"没识别出滚动"，不会乱拼。
- **单实例是「转交」而不是「并行」**：第二次启动会把请求（显示窗口 / 框选 / 贴图）
  交给已经在跑的实例，然后自己退出。全局热键本来就是进程独占的，
  让两个实例同时跑只会得到「按了热键没反应」。
- **双击启动仍可能有一帧级别的控制台闪动**：Windows 在 `CreateProcess` 时就给控制台
  子系统程序建好了窗口，我们只能在拿到 CPU 之后 `FreeConsole` 掉它。
  要做到完全无闪需要拆成 GUI / CLI 两个 exe，已记在路线图 M5-A，目前判断不值得。
- **商用化第一轮的"设置 → 行为"连线只在代码层面成立**：贴图布局与 JPEG 质量有单测覆盖，
  关闭到托盘与单实例有端到端探针（`tools/probe/`），但窗口层级、投影外观这几项
  **还没有做真人点击验证**，细节见 [docs/HANDOFF.md](docs/HANDOFF.md) 第 12.5 节。
