# 路线图

核心链路和大部分智能能力已经交付。下面只写"还有什么"，逐版本的改动在 `CHANGELOG.md`，历史决策在 `docs/HANDOFF.md`。

## 已经做完

截图与标注：热键唤起全屏冻结遮罩、八向调整、放大镜取色、八种标注、撤销重做、复制或保存、贴图窗口、命令行模式。

手感与精度：窗口和控件级吸附、区域记忆、界面 DPI 自适应、贴图透穿与透明度、原生另存为对话框。

智能能力：Windows 自带 OCR（可换成自建 PaddleOCR）、滚动截屏（自动滚与手动滚两种）、截图历史、逐行对照。

交付：便携包和安装包、单实例、开机自启、诊断面板、日志与配置的便携模式。

## 还没做

### 代码签名

没有证书，所以 SmartScreen 会提示未知发布者，Defender 也误报过一次 `Behavior:Win32/Persistence.A!ml` 并拦截执行。原因是程序确实会写开机自启项、常驻全局热键，无签名时这类行为没有信任来源。根治只能靠证书。

### 多显示器混合缩放

开发机只有一块屏，混合缩放（比如一块 100%、一块 150%）没有真机验证。代码里遮罩按物理像素处理，理论上可行，但没有证据就不敢说做到了。

### 屏幕翻译与以图搜图

两者都需要一个 HTTP 端点：翻译要 OCR 文本加机器翻译，搜图要把选区交给图片接口。程序里不内置服务，因为这类服务没有免费的稳定选项。接口层已经具备（在线 OCR 就是这个模式），缺的是端点。

### macOS 和 Linux

捕获和后端已经用 `ScreenCapture` trait 隔开，热键和托盘也有跨平台库。但 Wayland 下的 portal 不给帧缓冲，没法做冻结遮罩，要按 compositor 分别适配，这块工作量比看起来大。

## 不打算做

- 启动时间再压 100 ms：改动大、收益小，当前冷启动到可交互在半秒左右
- 自动滚动改成默认开：部分程序忽略合成滚轮消息，默认开会制造"滚不动"的困惑

## 怎么验证

每项能力都有对应的探针，清单在 `tools/probe/README.md`。提交门禁 `tools/ci/check.ps1` 会跑 clippy、单测、i18n 表、文档引用和 release 构建；桌面探针单独用 `tools/probe/run_all.ps1` 跑。文档里的数字都来自这些探针。
