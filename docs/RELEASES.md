# Cuter 发布说明（面向用户）

这个文件是给**下载页 / 更新提示**用的：用用户能看懂的话说清楚「这是什么、这一版多了什么、
有什么限制」。逐轮的工程细节在 `CHANGELOG.md`，实现来龙去脉在 `docs/HANDOFF.md`。

**写作规矩**：只写用户能感知的变化；数字必须实测过（来源见 `docs/HANDOFF.md`）；
限制要写出来，不藏。版本清单必须与 `CHANGELOG.md` 对齐（有脚本查，见文末）。

---

## 这是什么

Cuter 是一个 Windows 截图 / 标注 / 贴图 / 取字 / 滚动截屏工具，纯 Rust 写的。

* **小**：单个 exe **8.2 MB**，磁盘占用 ~7 MB，没有安装运行库、没有 Electron、没有浏览器内核
* **快**：双击到界面可交互中位 **364 ms**；按热键到遮罩出现中位 **86~116 ms**
* **省**：托盘待命工作集约 **56 MB**，几乎不用 GPU（待命时 **0.08%**，不采图时不出帧）
* **离线**：取字用 Windows 自带的 OCR 引擎，不下载模型、不联网

## 装哪个

| 你要的 | 下载 | 说明 |
|---|---|---|
| 免安装 | `cuter-<版本>-portable-x64.zip` | 解压即用。配置 / 日志 / 历史 / 默认保存目录**全部在 exe 旁边**，不碰系统 |
| 安装 | `cuter-<版本>-x64-setup.exe` | 装到 `%LOCALAPPDATA%\Programs\Cuter`，不需要管理员；可选开机自启、桌面图标；卸载保留你的配置 |

默认热键（设置里都能改）：

| 热键 | 动作 |
|---|---|
| `Alt+C` | 框选截图 |
| `Alt+X` | 截当前显示器 |
| `Alt+S` | 滚动截屏（框选后回车开始滚；按 `A` 让程序替你滚） |
| `Alt+V` | 把剪贴板里的图贴到屏幕上 |
| `Alt+H` / `Alt+G` | 隐藏/显示本组贴图 / 切到下一组贴图 |
| `Alt+O` | 识别屏幕上的文字 |

## 最近更新

#### 0.1.70 —— 手动滚动截屏补上验证

滚动截屏有两种用法：程序自己滚（自动），和人来滚、程序只负责拼。第二种是用户实际在用的，
却一直没有自动化验证——scroll_auto_e2e.ps1 只覆盖第一种，而且在当前机器上还会 SKIP。

scroll_manual_e2e.ps1 填补这个洞：它把配置改成手动模式，滚十四轮模拟人手工滚动，然后
读应用日志里的 scroll-done，要求帧数大于一、拼出来的图比选区高。实跑 23 帧、
750×550 的选区拼成 750×3493。

### 0.1.69 —— 更新检查不再每次都联网

* 启动时检查更新，**一天最多一次**；手点「立即检查」不受这个限制
* 不想升某个版本？「设置 → 关于」里点「跳过这个版本」，以后不再提它（可以随时取消）
* 开机那几秒网络还没起来导致的失败，会自动重试一次

## 0.1.68 —— 日志里"每句话写两遍"的根因找到了

双击启动时程序会丢掉 Windows 附赠的那个控制台，但那三个标准句柄的**数值**还留在
进程环境块里。紧接着打开日志文件时，系统把这个数值又分配给了日志文件——于是"写 stderr"
就写进了日志文件，控制台那一份和文件那一份叠在一起，看起来就是每句话两遍。
现在丢控制台之后顺手把三个句柄槽清空。连续启动 6 次，重复 0 处（修复前约一半的启动会重复）。

### 0.1.67 —— 贴图边上那圈灰边没了

贴图窗口四周原来留 12 像素画投影，在浅色桌面上看着像**一圈灰边框**；图片圆角大的时候，
四角还会露出一小块方的灰边。现在留白收到 7 像素、九层更淡的叠加、整体下移 1.5 像素，
每层圆角跟着图片走。贴着图片那圈才有一点暗，往外很快消失——是投影，不是相框。
拖边缘缩放没有变难（抓取范围仍含这圈留白，实测右边缘 439×250 → 318×183）。

### 0.1.66 —— 中文方框字不再出现

界面上偶尔整片中文变成方框（□）。原因是界面字体装载/卸载的时机：字体卸掉之后再开窗口，
那一帧还没有中文字形。现在字体装一次就不卸了，任何窗口第一次打开都是正常的字。
任务管理器里的内存在闲置 30 秒后照样还回去，看到的工作集没有变化。

### 0.1.65 —— 待命时"点了没反应"的三处修好了

上一版为了省电把待命心跳放宽到最长 4 秒，结果三处"等下一帧"的动作变慢：托盘右键菜单按
`Esc` 要三四秒才收、第二个实例转发的请求（比如命令行贴图）要等几秒、更新检查在开发机上
被占用端口挡了一下。现在菜单当场收起、外部请求一进来就把界面叫醒。

### 0.1.64 —— 屏幕上沿拖动不再搬走画面

上一版修的是贴图窗口，这条报的是**截图遮罩**：把鼠标放到屏幕上沿（含两个上角）按住左键拖，
整块冻结画面会被系统当成"拖标题栏"搬走。现在遮罩自己接管了命中判定，上沿一按就是框选。
0.1.63 的贴图缩放修复同时保留。

### 0.1.63 —— 贴图可以拖边缩放了

贴图窗口的四个边和四个角现在都能拖：指针移上去先变成缩放箭头，按下拖动就改大小。
拖右边/下边时左上角不动，拖左边/上边时对面那条边不动（窗口跟着指针挪），拖角两轴一起缩放。

顺带修掉一个老毛病：以前用滚轮缩小贴图，只有图片变小、窗口不变，图周围留出一圈空边；
现在窗口跟着缩。

### 0.1.62 —— 控件拉齐、说明减负、待命更省

输入框、下拉框、按钮统一成 28 px 高，按钮内边距也放大一档，不再"细狗"；一大批
技术味很重的说明文字压成一句话或直接删掉，界面上只留用户需要知道的那半句。

关于「内存一直在涨」：实测私有字节全程平线（29 MB），涨的是工作集——空闲裁剪把页换出后，
每秒一次的重绘又把代码页摸回来。现在待命重绘退避到 4 秒一次：GPU 平均 **0.094% → 0.036%**，
90 秒内的工作集爬升从 6.1→12.5 MB 降到 7.4→8.8 MB。不是泄漏，拆分 DLL 也帮不上这个忙。

### 0.1.61 —— 设置界面的对齐与留白

右边不再贴窗口边（和左边一样留 16 px）；说明文字改成折行显示，最多两行，不再一律截成
「…」；长文字悬停只弹一个气泡（以前 egui 的和自绘的会叠成两个）；所有下拉框和输入框
统一成同一个宽度。

### 0.1.60 —— 设置界面的六处打磨

五条反馈其实是一个根因：每次打开窗口时，控件拿到的是系统的旧配色，不是应用自己的主题，
于是浅色模式下出现"浅底浅字"。一并修了：下拉框与输入框的字色和底色、两个滑块的轨道与
手柄、主按钮做成一体式分裂按钮（右半是「▾」菜单），以及新建窗口第一帧可能没装字体导致
的豆腐块。托盘菜单也收紧了：整张 **407 → 355** 逻辑像素（本机 125% 缩放下实测 509 → 444 物理像素）。

### 0.1.59 —— 配置读坏时会告诉用户

解析失败不再是静默回退：状态栏直接说明已回退默认值、原文件备份在哪。备份文件名带时间戳
（旧版固定叫 `config.toml.bak`，第二次读坏会盖掉第一次的备份）。文件不存在不算读坏，
首次运行不会误报。

### 0.1.58 —— overlay 探针的 5 px 是合成输入的偏移

应用日志显示合成按下稳定落在请求坐标上方 1 px，松手时指针再滞后几像素，于是 380×230
测成 380×235。探针第 C 步的容差放宽到 ±6 px，但"重画而不是移动"的核心判据还在；
拖拽助手在松手前加了 150 ms 沉降。

### 0.1.57 —— 热键延迟的"回归"查清了：不是代码

同机交替跑 0.1.51 与 0.1.56：中位 181 ms vs 180 ms。旧文档里 113/156 ms 在今天这台机器上
任何构建都复现不出来，属于机器状态差异。顺带把 `perf_probe` 的热键采样从 5 次加到 9 次、
补上 25/75 分位与"抖动倍数"，免得再被单次运行带偏。

### 0.1.56 —— 托盘闲置时把工作集还给系统

托盘待命时工作集 58.8 MB，闲置 30 秒后 6.1 MB（私有提交不变）。这只是把页还给系统，
不是真的省了内存；代价是下一次热键多花约 8 ms。配套探针 `idle_trim_probe.ps1` 会真等
40 秒来验证它。

探针工具链两处调整：`run_all.ps1` 对失败探针重试一次（重试才过记 `PASS*`、单独报数）；
`scroll_auto_e2e.ps1` 在"选区底下没有可滚动窗口"时改报 SKIP 而不是 FAIL。

### 0.1.55 —— README 的数字重新量过

门面上的数字落后了：exe 7.9 → **8.6 MB**，常驻内存 87~97 → **149~156 MB**（工作集）、
51~52 → **69~77 MB**（私有），热键到遮罩中位 113 → **147 ms**。都用发出去的便携包里的
`cuter.exe` 复量，并写清复现命令。没有代码改动。

### 0.1.54 —— 读数说清楚量的是哪条路径，自动滚动不再滚错窗口

自动滚动发的滚轮只会落到光标底下那个窗口；选区中心被别的窗口盖住时，用户按下
"自动滚动"看到的是一动不动。现在发之前先把该点所在的顶层窗口提到前台。

`latency_probe` / `perf_probe` 的输出现在带 `backend=gdi|dxgi`：GDI 与 DXGI 差着几十毫秒，
旧日志只写数字，事后没法比。同一轮把 27 条探针（含以前从没跑过的
`installer_e2e` / `leak_probe` / `idle_gpu_probe` / `history_e2e`）全跑了一遍：全过。

本机复测：热键 → 遮罩中位 GDI 184–196 ms、DXGI 190 ms，捕获段中位 137–168 ms，
冷启动到首帧 335–408 ms。捕获段与旧记录持平；遮罩绘制段比 0.1.x 时期的 156/116 ms
慢约 25%，本轮未定位，已记进 HANDOFF 第 75 节。

### 0.1.53 —— 真 PaddleOCR 从手工验证变成一条探针

0.1.52 证明了"接真引擎能用"，但那是一次手工命令。这一版把它包成
`tools/probe/paddle_ocr_e2e.ps1`：自动起本机 PaddleOCR、驱动应用、断言认出至少 3 个块、
再关掉服务。没装 venv 的机器上它 SKIP（退出码 2），不会把套件染红。

实测（本机，PaddleOCR 2.9.1）：11 个块，约 1.9 s。见 HANDOFF 第 74 节。

### 0.1.52 —— 真的接上了自建 PaddleOCR

- 在线 OCR 原来只对着自己写的假服务端验过。这次在本机用 PaddleOCR 2.9.1 起了真服务，
  端到端跑通：Cuter 把框选的图 POST 出去，真引擎认出 11 个块，面板上显示真实词框。
- 顺手把四个子窗口的标题接进了界面语言（之前切英文后标题还是中文）。

### 0.1.51 —— 审计表按代码重新对了一遍

没有新功能，只有一次"账实相符"：

- `docs/config-audit.md` 里三行重复、三行写着"已删除"其实早就在用——重写。
- 删掉从未生效的 `ocr.model_dir`，以及 8 个没有任何调用者的 `pub fn`。
- `tools/docs/audit_config.py`：以后一条命令就能复查"每个配置项有没有人读"。

### 0.1.50 —— 横着滚，也拼得起来了

滚动截屏往横里滚的时候，长图以前要么拼不出来、要么凭空长高一截：一片底色在匹配算法眼里
「怎么滚都能对上」，于是空白行被当成新内容，方向还被锁死在纵向。这一版把「要追加的行必须
真有内容」写成硬条件，静止帧不再清掉换方向的投票，两次投票的步长也允许整数倍关系。

同时把探针的靶子从「多行 EDIT」换成「一条 4 万像素宽的长行（自绘静态控件）」——
旧的靶子带 `ES_AUTOHSCROLL` 也照样按宽度折行，横向根本滚不动，所以这条探针一直半盲。

### 0.1.49 —— 逐行对照：指着哪一行，哪个框就亮

识别结果面板右下角的逐行列表里，鼠标移到某一行，左边图上对应的框会加粗高亮；反过来把
鼠标放到图上某个框上，右边对应那一行也会亮起来。这个「双向对照」从 0.1.30 起就写在面板
的提示里，但列表这一侧的联动一直没生效，现在补上了。

* 只改了界面里的悬停判定，识别本身、复制、导出都不受影响。
* 没有新增开关，也没有新增网络请求。

### 0.1.48 —— 竖着排的字，从右往左读

* 识别竖排文字（一列一列从右往左写的中文/日文）时，编号和文本顺序现在按「右列 → 左列、
  每列从上到下」排好
* 只有整页都是竖排时才这么排；横竖混排的页面顺序不变
* 图上框、右侧文本、复制出来的纯文本，三处顺序一致

### 0.1.47 —— 有新版本会告诉你了

* 设置 → 关于 里可以填一份「版本清单地址」，启动时帮你对一下版本
* 发现新版本：状态栏提示一句，关于页里给个「打开下载页」按钮
* 只查、只提示，**不会自动下载、不会静默替换你的程序**；地址留空就一个字节都不发（默认如此）
* 没有官方发布渠道，所以地址要自己填——有内网分发页的人才用得上

### 0.1.46 —— 斜着排的字也能框准了

* 识别结果面板的高亮框改成按真正的四个角画：斜排、竖排的文字框不会再套一个歪掉的方框
* 鼠标判断也跟着走四边形，指在框外不会再误点亮那一行
* 这一条主要服务「在线接口」引擎（它才会给出旋转框），系统自带引擎仍然是矩形

### 0.1.45 —— 长截图能看见进度了

* 滚动截屏面板多了一条细进度条：已经拼了多少 / 最多能拼多少（长度上限可在设置里改）
* 上限关掉时这条不显示，面板不会白占一行
* 顺手把遮罩的拖拽提示、吸附线、长截图进度都在真机上核了一遍，和设计稿一致

### 0.1.44 —— 取字可以走你自己的服务了

* 「设置 → 文字识别」里可以选**在线接口**：把框选的图 POST 到你填的地址（自建 PaddleOCR
  之类的服务），识别结果一样进面板
* 只支持 `http://`（没有 TLS）；默认地址是 `http://127.0.0.1:8866/ocr`，填错了会有明确提示
* 修好了两条热键：「识别文字」(Alt+O) 与「贴图并识别」以前按下去没反应，现在真的能取字了
* 没装服务也不影响：内置的 Windows 离线识别照旧是默认引擎

### 0.1.43 —— 取色读数不再碎成三块

放大镜底下的取色信息，原来是"一块色块 + 两个深色小胶囊"，宽度不一，看着像三块碎片。现在合成一张和放大镜等宽的卡片：

- 第一行是 22×22 的当前色块和 `#RRGGBB`；
- 第二行 `rgb(r, g, b)`；
- 第三行是这个像素在屏幕上的坐标。

卡片默认贴在放大镜下面，靠近屏幕底边时自动翻到上面，不会被切掉。功能没变，只是把读数收拢成一张卡片。

### 0.1.42 —— 托盘菜单换了新样子

右键托盘图标弹出的菜单不再是 Windows 自带的那种，而是本程序自己画的一块面板，和设置窗口同一套配色：

- 顶上写清楚版本号；
- 每一项右边的快捷键照旧（框选截图 Alt+C、截取当前显示器 Alt+X、贴图 Alt+V、隐藏/显示所有贴图 Alt+H、下一个贴图组 Alt+G）；
- 「退出 Cuter」用红色标出来，不再和别的项目长得一样；
- 底下一行提示「左键单击托盘图标 = 框选截图」，忘了快捷键时可以瞄一眼。

功能没变，位置也还是弹在鼠标旁边（贴屏幕边时会自动往里收）。

### 0.1.41 —— 贴图"被穿透卡住"多了第二个出口

鼠标穿透打开后，贴图收不到鼠标消息，右键菜单点不到，这是设计使然；但出口原来只有托盘菜单一项。
现在也可以直接命令行：`cuter --clear-pin-click-through` —— 正在运行的那个实例会立刻取消所有贴图的
鼠标穿透（同时把配置里的开关关掉，避免下次贴图又变成点不动的状态）。

适合绑到快捷方式、脚本或自动热键上。

### 0.1.40 —— 主题跟随更可靠

- 系统主题与应用主题不一致时（例如系统是浅色、应用选了曜夜紫），贴图右键菜单里的滑杆与开关、
  识别结果 / 截图历史 / 滚动截屏面板的底色不再串主题；
- 浅色皮肤（薄荷奶白）逐屏走查过一遍：设置窗口与截图历史面板的文字、控件对比度正常。

### 0.1.39 —— 滚动截屏面板按设计稿重写

滚动截屏（`Alt+S` 框选后按回车）的控制面板换了新样子：顶栏一眼看清帧数、拼接尺寸与滚动方向，
中间是实时拼接预览，底部只有一颗实心按钮「完成 (Enter)」，其余都是描边或纯文字。

## 已知限制（先说清楚）

* **没有代码签名**，所以 Windows SmartScreen 会提示"未知发布者"，而且本程序被 Defender
  误报过一次（`Behavior:Win32/Persistence.A!ml` 并拦截执行）——原因是它确实会写开机自启项、
  常驻全局热键，而无签名的程序这类行为没有信任来源。需要签名证书才能根治。
  临时办法：在提示里选"仍要运行"，或把 exe 加入 Defender 的排除项。
* **只在单显示器上验证过**（开发机只有一块屏）。多显示器混合缩放（例如一块 100%、一块 150%）
  没有真机验证，请谨慎使用并反馈。
* **取字用的是系统 OCR**：中文需要系统装了中文语言包；竖排 / 旋转文字目前只能按轴对齐矩形返回。
* **自动滚动**（滚动截屏里按 `A`）对部分程序无效——它们忽略合成滚轮；遇到这种程序请手动滚。
* **在线能力都还没做**：OCR 在线引擎、屏幕翻译、以图搜图需要你自己提供 HTTP 端点，
  目前没有内置服务。

## 配置在哪

| 装法 | 配置 / 日志 / 历史 |
|---|---|
| 便携版 | 全部在 `cuter.exe` 旁边：`config.toml`、`logs\`（日志）、`data\history\`（截图历史）、`Screenshots\`（默认保存目录） |
